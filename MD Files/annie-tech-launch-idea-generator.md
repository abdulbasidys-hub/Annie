# Tech Launch Idea Generator

## Purpose

Generate ONE original technology-based launch idea that can be built from scratch as a standalone crypto/memecoin project.

This skill is NOT about creating technology around a meme.

The tech idea must be independently generated. It must stand on its own as an interesting product, system, experience, or interactive mechanism.

The objective is to find something that people would genuinely want to use, play, explore, participate in, return to, or share.

---

## Technology Directions

For every generation, consider these six directions:

1. Game / Competition
2. AI Agent / AI Tool
3. Social Interaction
4. Live / Dynamic System
5. Useful Tool
6. Visual / Generative Experience

Choose ONLY ONE direction for the final idea.

Do not generate six ideas.

Do not automatically combine multiple directions.

Choose the direction that best fits the opportunity Annie identifies.

---

## What Annie Should Look For

A strong technology idea should have as many of these qualities as possible:

- Interactive
- Difficult to replicate with a basic website
- Has a clear user action
- Produces an interesting result or outcome
- Gives users a reason to return
- Has potential for organic sharing
- Can be built by a small technical team
- Has a clear MVP
- Can exist as a real product, not merely a landing page
- Can naturally connect to a token if appropriate

The technology itself should be the attraction.

Do not create a token first and then invent a weak reason for people to visit the website.

---

## Idea Selection

Before generating the final idea, internally evaluate all six directions.

Ask:

- Which direction has the strongest opportunity right now?
- Which direction could produce the most interesting user experience?
- Which direction has room for originality?
- Which direction can realistically be built?
- Which direction could create repeat usage?
- Which direction could produce something people want to share?

Then select ONE direction.

Do not show the internal comparison unless specifically requested.

---

## Originality

Use current internet, crypto, AI, gaming, and technology trends as inspiration when available.

Study what people are building, but do not simply copy an existing project.

Look for:

- Existing concepts that could be reinterpreted
- Underused interaction patterns
- New combinations of accessible technology
- Interesting problems that can become entertaining products
- Things people are already doing manually that software could make interactive
- Experiences that are technically impressive enough to stand out

The final concept should have its own identity.

Avoid superficial changes to an existing project.

---

## Token Integration

The token does NOT need to be the center of the technology.

If a token naturally improves the idea, Annie may suggest roles such as:

- Access
- Rewards
- Competition
- Ownership
- Progression
- Payments
- Voting
- User incentives
- On-chain state
- Creator rewards
- Dynamic reward pools

Do not force token utility.

A good technology idea with a natural token connection is better than a weak technology idea designed only to justify token utility.

---

## Interaction

Think beyond static pages.

The user should DO something.

Examples of interaction patterns Annie may explore:

- Play
- Compete
- Generate
- Upload
- Transform
- Predict
- Vote
- Control
- Challenge
- Collaborate
- Watch a system evolve
- Interact with an AI agent
- Trigger a live event
- Build something
- Discover something
- Influence an outcome

These are examples, not a fixed list.

---

## Buildability

The idea should be ambitious enough to be interesting but realistic enough for a small technical team to build.

Prefer:

- A clear MVP
- Existing APIs and infrastructure where appropriate
- Web applications
- AI APIs
- Blockchain integrations where useful
- Real-time systems
- Simple but clever mechanics

Avoid ideas that require:

- Massive infrastructure from day one
- Millions of users before the product works
- Impossible technical requirements
- Unclear development paths

---

## Output Format

Return exactly ONE idea using this structure:

### Technology Direction
[One of the six directions]

### Concept
[Name of the concept + one-sentence explanation]

### What We Build
[What the actual product/system/experience is.]

### How It Works
[Brief explanation of the user's interaction and the system's behavior.]

### Core Hook
[The single thing that makes this interesting.]

### Why People Would Use It
[Why someone would choose to interact with it.]

### Repeat / Share Loop
[Why users might return or share the experience.]

### Token Connection
[Explain how the token could naturally fit. If there is no strong connection, say: "No forced token connection."]

### MVP
[The smallest practical version we could build.]

### Build Difficulty
[Low / Medium / High + one short explanation.]

---

## Hard Rules

- Generate ONE idea only.
- Choose ONE technology direction.
- The tech idea must be independent of Annie's meme idea.
- Do not build a website around a previously generated meme.
- Do not simply create a landing page.
- Do not automatically make it a game.
- Do not automatically use creator rewards.
- Do not automatically use AI.
- Do not force token utility.
- Do not copy an existing memecoin project.
- Do not recycle previous concepts with superficial changes.
- Prefer a strong core mechanic over many features.
- The final idea must be something we could actually build.
- The technology must be a meaningful part of the project, not decoration.
